## 데이터·크롤 진단 (핵심)

1. **이름 스키마 불일치** — `name` 문자열 vs `{ko,en,…}` 혼재, `ko` 누락 다수.
2. **지역 코드 오염** — `서울특별시`, `경상남도`, `거제시` 등 비정규 코드.
3. **트렌드 전국화는 시드만 넓힘** — 결과·쿼리는 여전히 거제 편중. 카테고리성 쿼리(`…맛집`, `…성지`)가 쓰레기 POI를 만듦.
4. **소셜 export ↔ git** — force-add로 워크플로는 통과하지만 리포 비대화 리스크.
5. **테스트 부재** — 회귀는 수동/빌드에 의존.

## 추천 개발 방향

### P0 — 데이터 품질 게이트 ← **현재 스프린트**

- 크롤 저장 전: **이름 객체 강제**, 쓰레기/카테고리 POI 하드 게이트
- `province`/`city` **코드 정규화** + 기존 JSON 일괄 마이그레이션
- string `name` → `{ ko, en, … }` + 누락 `ko` 채우기
- `npm run validate-places` 스키마 검증

### P1 — 전국 커버리지 균형

- 트렌드/플레이스 시드 **권역 쿼터**
- 카테고리성 큐레이션 쿼리 제거·구체 POI로 교체
- 어드민에 지역별 장소 수 / 트렌드 연결률

### P2 — 운영 비용·안정성

- `social-exports`를 git 밖(Artifacts)로
- 스크래퍼 lint 정리, CI에 스키마 검증 연결

### P3 — 제품 확장 (데이터 안정 후)

- 플래너 ↔ 가이드봇 일정 연동
- 검색/필터 고도화
- 실 analytics (히트뱃지 대체)
