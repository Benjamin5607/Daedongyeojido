## 데이터·크롤 진단 (핵심)

1. **이름 스키마 불일치** — `name` 문자열 vs `{ko,en,…}` 혼재, `ko` 누락 다수.
2. **지역 코드 오염** — `서울특별시`, `경상남도`, `거제시` 등 비정규 코드.
3. **트렌드 전국화는 시드만 넓힘** — 결과·쿼리는 여전히 거제 편중. 카테고리성 쿼리(`…맛집`, `…성지`)가 쓰레기 POI를 만듦.
4. **소셜 export ↔ git** — force-add로 워크플로는 통과하지만 리포 비대화 리스크.
5. **테스트 부재** — 회귀는 수동/빌드에 의존.

## 추천 개발 방향

### P0 — 데이터 품질 게이트 ← **현재 스프린트**

- 크롤 저장 전: **이름 객체 강제**, 쓰레기/카테고리 POI 하드 게이트
- `province`/`city` **코드 정규화** + 기존 JSON 일괄 마이그레이션
- string `name` → `{ ko, en, … }` + 누락 `ko` 채우기
- `npm run validate-places` 스키마 검증

### P1 — 전국 커버리지 균형

- 트렌드/플레이스 시드 **권역 쿼터**
- 카테고리성 큐레이션 쿼리 제거·구체 POI로 교체
- 어드민에 지역별 장소 수 / 트렌드 연결률

### P2 — 운영 비용·안정성

- `social-exports`를 git 밖(Artifacts)로
- 스크래퍼 lint 정리, CI에 스키마 검증 연결

### P3 — 제품 확장 (데이터 안정 후)

- 플래너 ↔ 가이드봇 일정 연동
- 검색/필터 고도화
- 실 analytics (히트뱃지 대체)

## Tripadvisor 등과 비교했을 때 부족한 점
**(대동여지도 정체성 기준으로 — 예약·UGC 플랫폼이 되라는 뜻이 아님)**

정체성: **글로벌 여행자를 위한 한국 큐레이션 디렉터리** (테마·트렌드·로컬젬·플래너·소셜 초안).  
Tripadvisor/Google/Naver는 **규모·신뢰·거래**가 강하고, 우리는 **한국 맥락의 해석·큐레이션 밀도**로 싸워야 한다.

| 부족한 점 | 왜 아픈가 | 우리식 대응 (정체성 유지) | 상태 |
|-----------|-----------|---------------------------|------|
| **깊이 있는 “왜 지금 / 어떻게 가는가”** | TA는 리뷰 양이 많고, 우리는 스크랩 리뷰·짧은 설명 위주 | 테마별 에디토리얼 한 단락 + 로컬 팁(산행 난이도·시즌·접근) — UGC 복제 금지 | ✅ 테마 에디토리얼 + `difficulty`/`seasonTips`/`accessTips`/`editorial` |
| **의사결정 신뢰 신호** | 별점·리뷰 수·최근성·사진 다양성이 약함 | 기존 스크랩 리뷰의 **신선도·출처 라벨** 강화, “로컬젬” 기준 투명화 | ✅ `fetchedAt`·출처 라벨 + Local Gem 기준 공개 |
| **전국·시즌 커버** | 거제 허브 편중은 디렉터리 신뢰에 직격 | 권역 쿼터 크롤 + **산행 테마**처럼 수요 테마로 전국 확장 | ✅ `scraper/config.js` 권역 분산 시드 |
| **실용 플랜 디테일** | TA/지도앱은 이동·영업·혼잡 정보가 붙어 있음 | 예약/계정을 넣지 말고, 플래너에 **테마별 동선 템플릿**(예: 서울 근교 산행 1일) | ✅ 플래너 테마 템플릿 (계정 없음) |
| **검색·발견 UX** | 지도 탐색·필터·저장 리스트가 얇음 | 지도는 아웃바운드 유지하되, **테마×지역 교차 필터**와 저장/공유를 깊게 | ✅ 홈/지역 교차 필터 + 장소 공유·플래너 저장 힌트 |
| **커뮤니티 모멘텀** | 리뷰·사진 UGC 루프 없음 | 온사이트 UGC 대신 **트렌드·소셜 초안**으로 “지금 뜨는 한국” 포지션 유지 | 유지 (UGC 미도입) |

**베끼지 말 것:** 호텔/투어 예약, 전 세계 POI 확장, 리뷰 전쟁.  
**이길 축:** 한류·미식·산행처럼 *한국에서만 선명해지는 테마 렌즈* + 트렌드 속도 + 로컬젬.
